# Virida Notes

![Virida Notes logo](virida-notes-lockup.png)

A free, open source, web based notes app inspired by the way Evernote works, with one big difference: your notes live in storage you own, not on our servers. There are no Virida Notes servers. The app is a single HTML file that runs entirely in your browser, and your notes live in your own Google Drive.

Live app: https://clytherin-tech.github.io/snakescale/

## Why Virida Notes

- Free forever. The app is open source and your storage is your own Google account.
- Private by design. Notes are stored as plain Markdown files in a Drive folder that only you control.
- Works anywhere. Any modern browser on PC, tablet, or phone. No install required.
- Your data is yours. Export any time by downloading the files. It is just files.

## Features

- One simple storage story (simplified in v2.0): sign in with Google once and your notes and attachments live in your own Google Drive, in one folder named SnakeScale Notes. There is no storage choice to make, no token to paste, and no app password. Earlier versions also offered a GitHub repository backend and a pCloud attachment provider; both were removed in v2.0 so the app has exactly one sign in and one folder
- Notebooks, notes, and tags, with local full text search
- Rich text editor with headings, lists, and checklists
- Clickable, editable links in notes (v1.3.1, reworked in v1.3.2, rebuilt in v2.9.0): Ctrl+click (Cmd+click on a Mac) opens a link in a new tab, and resting the mouse on a link (or clicking or tapping it) shows a dark link bar where the address itself is clickable to open the link, and icon buttons edit the link's text or address in place, copy the address, or remove the link while keeping its text. Only http, https, and mailto links can be opened or saved
- Link display modes (new in v2.9.0): the link bar's three dot menu switches a link between Text (an ordinary link), Mention (an inline chip with the site's logo and title), and Preview (a block card with the page's cover image, title, and description), and can also copy the address or delete the link and its text together. The mode is saved in the note itself. Mention and Preview fetch the page's real title, description, image, and logo the first time they are used on a link; see the privacy notes
- Links to other notes (new in v2.1.0): the Insert menu's Link to Note opens a searchable picker of your notes, and the link it inserts opens that note inside the app, switching the list to All Notes when the target is not in the current view. A link whose target sits in Trash or the Archive, or no longer exists, says so in a toast instead of navigating. Since v2.10.0 these links show the same hover link bar as web links (with the target note's current title as the label, an edit state that can retarget the link through the picker, and a copy action that copies the note link itself), and they have their own display modes, Text, Mention, Title, and Preview, rendered live from the target note. Since v2.12.0 you can also type "@" in a note: a Results popup under the caret lists the notes whose titles match what you type (archived notes included, Trash never), most recently updated first, with a Create new note row that makes a note with the typed title in the current notebook and links to it; Enter, Tab, or a click inserts the link, and links created either way now start in the Mention display mode (links saved earlier keep the mode they have)
- Export the open note (new in v2.1.0): an Export menu in the editor footer saves the open note as a plain text file (title first, then the body with checklist items as ballot box lines), as a real Word .docx document generated in the page with no library, or as a PDF through a clean print view the browser saves
- Import notes (new in v2.1.0): the Import button in the notes list toolbar turns .txt, .docx, and .pdf files into notes in the current notebook. Text files split into paragraphs, Word files are unzipped and converted in the page, and each PDF becomes a note with the file attached through the Google upload flow. Several files can be imported at once, and any file that fails is named in the closing summary
- More Insert items (new in v2.1.0): a starter table with a header row, a code block, and inline code join attachments, links, dividers, and the date and time in the Insert menu
- A full formatting toolbar (new in v1.3): an Insert menu (attachments, links, checklists, dividers, date and time), text styles (headings 1 to 3, quote, code block), font family and font size pickers, text and highlight color palettes with custom colors, strikethrough, text alignment, indent and outdent, and remove formatting. Fonts, sizes, and colors are saved as inline CSS styles in the note body, never as font tags, so formatted notes render the same on every device
- Attachments and inline images (new in v1.2): files are stored in your own Google Drive, in an attachments subfolder of the same SnakeScale Notes folder that holds your notes, and your notes keep only a small reference to each file. The same single Google sign in covers notes and attachments. Attach from the Insert menu, by drag and drop, or by pasting an image. Publisher setup for the sign in button is a one time job for the app owner: see [ATTACHMENT_PROVIDERS_SETUP.md](ATTACHMENT_PROVIDERS_SETUP.md). End users never register a developer app.
- Attachments where you left the cursor (new in v1.6): files attached from the Insert menu or file picker are inserted at the caret position you had when you started attaching, and files dropped onto the editor land at the drop point. A run of several files inserts in order at that spot
- Inline PDF preview (new in v1.6): PDF attachments get a Preview toggle on their card. Expanding it fetches the document on demand and shows it right inside the note, in the place where the attachment sits, so a PDF can be read without downloading it first. The preview is view only state; it is never written into the saved note file
- Movable, resizable attachments (new in v1.6): attachment blocks can be dragged to a new position inside a note (on touch screens, cut and paste moves them instead). Clicking an inline image selects it and shows a corner handle; dragging the handle resizes the image, and the chosen width is saved in the note so it renders the same size on every device
- Voice notes with transcription (new in v2.14.0): the Voice note button beside Insert records from your microphone and shows your words appearing live as you speak, transcribed by your browser's built in speech recognition (Edge and Chrome offer it; the speech service is your browser maker's, and the app sends nothing itself). Stop saves the recording into your Drive as an attachment, playable right on its card in the note, and writes the transcript under it as plain text; Cancel discards the recording entirely. In a browser without speech recognition the recording is still attached, with a note that transcription is unavailable there
- Draggable blocks (new in v2.14.0): resting the pointer at the left edge of a paragraph, heading, list, table, code block, or attachment shows a six dot grip; dragging it moves the block up or down the note, with a line marking where it will land. List items get grips too and reorder within their own list, so checklist items move with their checkbox and done state intact
- Undoable attachment deletion (new in v1.7): removing an attachment, from its Remove button, the image menu, or the Delete and Backspace keys, takes it out of the note at once and opens a five second undo window, announced by a toast at the top of the window with the file name and an Undo button. The file is deleted from your Drive only when the window closes; Undo (or the block coming back, for example through the editor's own undo) cancels the deletion completely, and if the cloud delete cannot happen the attachment is restored and kept
- Inline images, no card (new in v1.7): image attachments sit in the note as plain images in the text, with no border, no card frame, and no name bar. File attachments, including PDFs with their inline preview, keep the card look
- Image grips and a three dot menu (new in v1.7, expanded in v2.11.0): clicking an image selects it with four corner grips for resizing (any corner works, proportions are kept) and a three dot button at its top right. The menu now runs the full image toolkit: a full screen preview, an annotate editor (pen, colors, text labels) and a crop tool whose saves upload the result as a new file and swap it into the note while the original file stays untouched in your attachments folder, transcribe (reads the text in the image and inserts it under the image; the OCR library loads from a CDN on first use, see the privacy notes), an editable caption saved with the note, image alignment (left, center, right, fill width, text wrapping, or free move, which lets you drag the image to any spot in the text), rename, download, print just the image, set as note thumbnail (shown on the note's card in the list), a Title view that collapses the image to a name bar, and Delete file through the undoable deletion above. A freshly pasted or dropped image can be selected, moved, and resized right away, without reopening the note
- Checklists without bullets, with real Enter behavior (fixed in v1.6): checklist items no longer show a stray list bullet in front of the checkbox, and pressing Enter at the end of a checklist item starts a fresh checklist item. Enter on an empty checklist item leaves the checklist, like other note apps
- A branded loading screen (new in v1.6): an animated tile S logo with a plain status line covers sign in and sync, and the note list fills in from the device cache behind it, so connecting never means staring at a blank screen. The sidebar shows the running app version at the bottom
- Pinned notes, trash with restore, and delete forever
- Archive (new in v1.5): tuck notes out of the way without deleting them. Archived notes move to their own archive folder and Archive view, stay out of the regular lists and search, open read only, and unarchive back to the notebook they came from at any time. Moving a note to Trash, restoring it, and deleting it forever also update the screen instantly now, with the storage work finishing in the background
- No app password, ever: sign in with Google is the only sign in. The Google token lives in memory while you use the app, the stored copy is encrypted, and a random device key encrypts the token store and the local note cache on that device. That device key is not a login and does not protect against someone using your unlocked browser profile
- Offline reading and editing from the local cache, with queued changes synced when you reconnect
- Tasks with reminder notifications (new in v2.24.0): real to-dos that live in your notebooks next to the notes, modeled on Evernote Tasks. Every task has a due date with an optional time, a flag, a priority, recurrence, and an optional reminder; each notebook that has tasks gets one Things to do tile in its list and in All Notes, and clicking it opens that notebook's tasks as a page in the editor; a Tasks view gathers all of them across notebooks. See the Tasks section below
- Idle auto-sync (new in v2.16.0): with the app open, changes made elsewhere (another device or browser signed into the same Google account) appear on their own within about half a minute of you pausing. The app checks Drive's change feed every 30 seconds and syncs only when something in the notes folder actually changed, and only once you are idle, so it never interrupts typing, a recording, or a drag. It can be turned off in Settings
- Conflict safety: if a note changed somewhere else, saving creates a conflict copy instead of overwriting it
- Note version history (new in v2.8.0): changing a previously saved note stores its previous state as a restorable version (at most one per 10 minutes, kept up to the count chosen in Settings). The History button in the editor footer previews versions read only and restores one after preserving the current note as a new version first
- A first run walkthrough and starter note (new in v2.13.0): a store seeded at first sign in opens a five step tour and creates a pinned starter note that demonstrates headings, formatting, a checklist, a table, and links. Settings has a Getting started section that replays the tour and adds the starter note on any store, so both can be tried any time
- A Settings dialog (new in v2.8.0): theme as a Light and Dark segmented control, Refresh connection, and the versions per note count live in one dialog opened from the sidebar menu, ready for future settings to join them
- Light and dark themes in the Deep Forest palette

## How to use it

1. Open the live app link above.
2. On the setup screen, continue to Google sign in. There is no SnakeScale Notes app password and nothing to fill in.
3. Click Sign in with Google and approve access. SnakeScale Notes creates a folder named SnakeScale Notes in your Drive for your notes, and attachments live in an attachments subfolder of that same folder, with the same sign in.
4. Start writing. On later visits SnakeScale Notes first tries a silent Google sign in renewal; if that is not available, it shows the Sign in with Google screen. Use Sign out in the sidebar to clear this device's local copies, the stored sign in, and the device key while leaving the Drive notes untouched.
5. On other browsers, repeat the setup and sign in with the same Google account.

## How your data is stored

Everything lives in one folder in your Google Drive, named SnakeScale Notes.

- One folder per notebook inside a notebooks folder
- One Markdown file per note, with simple front matter and an HTML body
- A trash folder for deleted notes, an archive folder for archived notes, and an index.json the app can rebuild from the folders at any time
- A catalog.json (new in v2.20.0): a small cache of everything the notes list displays (title, notebook, tags, preview, pin, thumbnail facts, and each note file's current revision), so loading the library reads one small file plus the folder listings instead of downloading every note body; a note's body is fetched when you open it or an operation needs it. The catalog is a cache only: the app rebuilds it from the note files whenever it is missing, damaged, or out of date, and the note files remain the only source of truth
- An incoming.json (new in v2.20.0): the drop box for notes added by other tools, documented under "Adding notes from other tools" below. It holds two lists, notes waiting to be imported and rejected entries, and stays empty until a tool writes into it
- A tasks.json (new in v2.24.0): every task in every notebook, in one small file the app keeps in step as tasks change. It is created the first time a task changes; a store with no tasks yet simply has no tasks.json. See the Tasks section below
- A versions folder (new in v2.8.0) with one JSON file per note holding that note's saved version history: previous titles, bodies, tags, and attachment references, newest first. The folder is created only when a note first gains a version, and index rebuilds ignore it just like the attachments folder
- Attachments are different on purpose: the binary files live in an attachments subfolder of the same SnakeScale Notes folder. The note file stores only a one line attachments list in its front matter (provider name and file ID) plus a placeholder in the body where the image or file card appears
- Upgrading from a version before v2.0: attachments used to live in a separate top level folder named SnakeScale Notes Attachments. Those files keep working where they are, because notes reference them by Drive file ID. On your first sign in after the upgrade, SnakeScale makes one best effort pass to move them into the new attachments subfolder; the old folder is left in place for you to remove when you are ready

## Tasks

Tasks (new in v2.24.0) are real to-dos that live alongside your notes, modeled on the way Evernote implements its Tasks feature and adapted to notebooks. A task is its own object, not a line inside a note: it belongs to a notebook, and it carries a title, an optional longer description, a due date with an optional time, a flag, a priority (low, medium, or high), a recurrence (none, daily, weekly, monthly, or yearly), and an optional reminder. Checklists inside notes are unchanged; tasks are the layer above them, for the things that carry dates and deserve a reminder.

Where tasks show up:

- In a notebook's list, and in All Notes, each notebook that has tasks gets one Things to do tile (new in v2.24.3, replacing the Tasks group the list carried through v2.24.2): a card like a note card, titled Things to do, with the notebook's name and its latest task activity in the meta line and a small pill showing how many of its tasks are completed out of the total. The tile sorts into the list by that activity time, like a note by its edited time. Clicking it opens that notebook's Things to do page in the editor: a breadcrumb, the same progress chip, a quick add for the notebook, and the tasks as a checklist with round checkboxes, word due labels at the right (Overdue in red, Due today, Tomorrow, or the date), the flag and the priority, and the completed tasks below their own heading, struck through and dimmed. Ticking a checkbox completes the task without opening anything (a recurring task rolls forward instead); clicking a row opens the task editor. The page is a view over the tasks only: it is not a note, and opening it writes nothing to any note file.
- The sidebar gains a Tasks entry directly under All Notes, with the open task count. The Tasks view lists every task in every notebook. It groups by due date (Overdue, Today, Upcoming, No due date, Completed), by notebook, or by priority, and filters to All, Open, Flagged, or Completed. A quick add row at the top creates a task in the notebook you pick; the New Task button beside it opens the full editor. Since v2.24.1 the Tasks view has its own pane: it takes the whole main area beside the sidebar while it is active (the notes list and the editor hide, and return untouched when you leave), its header shows the open count beside the title with a Find tasks search that filters the rows by title or notebook name, and its list is a table with a Title, Due date, and Notebook column header row and group headers that collapse and expand from a chevron.
- Completing a recurring task does not close it: its due date rolls forward by the interval (a monthly task due on the 31st lands on the last day of the next month), ready for its next round. Completing a plain task moves it to the Completed group, and unticking it there reopens it.

All tasks live in one file, tasks.json, in the same SnakeScale Notes folder as index.json, catalog.json, and incoming.json (notebook folders hold notes only, as always). The app reads it with the library, writes it as tasks change, and syncs it like the rest of the store, so tasks follow you across devices. If the file is damaged, the app shows an empty task list rather than failing, and it does not overwrite the damaged file until you actually change a task. Deleting a task removes it outright; there is no task trash in this version.

Reminders are notifications, generated on your device. When a task has a due date you can set a reminder for the due moment itself, 15 minutes or an hour before it, or a day before; a task with a due date but no time is due at 9:00 AM that day. The first time you set one, the app asks your browser for notification permission (there is also an Enable notifications button in the Settings Notifications section, which is also where the whole reminder feature can be switched off). While the app is open on a device, a scheduler checks every 30 seconds, and a due reminder appears as a notification naming the task, its notebook, and when it is due; clicking it focuses the app and opens that task's editor. Two honest limits: there is no SnakeScale Notes server and no push service, so a reminder cannot reach a device where the app is fully closed. What the app does instead is catch up: a reminder whose moment passed while the app was closed fires once when you next open it, and never twice for the same due moment.

Like everything else in SnakeScale Notes, tasks are plain data in your own Drive: anything with write access to the folder can read or edit tasks.json, and the format is the one described above.

## Adding notes from other tools

SnakeScale Notes signs in with the drive.file permission, which means Google only ever shows it files the app created itself. A note file another program uploads into a notebook folder is invisible to the app, and no index or catalog entry can change that.

The drop box works around it. incoming.json, in the same SnakeScale Notes folder, is a file the app creates and can always read, so anything with write access to that folder can add notes by editing its content:

- The file is a JSON object with two arrays: { "notes": [...], "rejected": [...] }.
- Each entry in "notes" is one complete note file as text: the same front matter and HTML body the app writes into a note's .md file (id, title, notebook, tags, created, updated, pinned, then the body after the closing front matter line). The notebook value must be the slug of a notebook that exists; an entry naming a missing notebook is imported into the first notebook instead, and the import report says so.
- On each sync the app imports new entries as ordinary notes it creates itself, removes them from "notes", and reports the counts on screen. An entry whose note id already exists anywhere in the store (notebooks, Trash, or Archive) is skipped as a duplicate and removed. An entry that is not note file text moves to "rejected" with a short error and the time, and is not tried again; fix the text there and move it back to "notes" to retry it.
- Attachment references in an entry's own front matter are removed on import, because the files they name are not visible to the app, and the import report counts the notes it happened to. Files themselves travel with the object entry form below instead.
- An entry may instead be an object: { "note": "<one complete note file as text, exactly as above>", "attachments": [ { "name": "photo.png", "mimeType": "image/png", "dataBase64": "<the file's bytes, base64 encoded>" } ] }. On import the app uploads each carried file itself, so it lands in the attachments folder as an ordinary attachment of the note: images are placed inline at the end of the body, and other files as attachment blocks there, in the order listed. Caps: 10 MB per attachment (decoded size) and 25 MB of attachments per entry (decoded). An item over a cap is skipped, and an item whose upload fails is skipped too, while the note and its remaining attachments still import. The import report counts the attachments imported, and names the ones skipped as too large and the ones that failed. The duplicate check runs before any upload, so reprocessing an entry never leaves orphaned files behind.

## Privacy and security notes

- Note sync talks to Google Drive from your browser, and Google's sign in script is loaded from Google only at the moment you click Sign in with Google. SnakeScale Notes can only see the Drive files it created (the drive.file permission), not your whole Drive.
- The app ships with the publisher's Google OAuth client ID built in (new in v1.4.2), so nobody is ever asked for a client ID. That ID is a public identifier, not a secret: Google locks its use to the web origins the publisher registered in Google Cloud, so it cannot be used to sign anyone in from anywhere else. If you fork SnakeScale Notes, register your own OAuth client in Google Cloud (free) and either replace the PUBLISHER_GOOGLE_CLIENT_ID constant in the app file, or set an override in the app settings value state.attach.googleClientId, which sign in still honors (there is no settings field for it in the app).
- Local copies on a device are encrypted with that device's random key, but the key lives on the same device. It scrambles local copies against casual snooping; it is not a login and it does not protect against someone using your unlocked browser profile. Sign out clears those local copies.
- Link info lookups (new in v2.9.0): when a link is shown as a Mention or a Preview, SnakeScale Notes looks up that link's address through Microlink (api.microlink.io) to fetch the page's title, description, cover image, and site logo. Only the link address is sent, never note text or Drive data. The result is saved in the note itself, so a link is looked up once, not on every view, and Text links are never looked up.
- Image transcription (new in v2.11.0): the image menu's Transcribe loads the Tesseract.js OCR library from the jsDelivr CDN the first time it is used, and only then. The recognition itself runs entirely in your browser on the image you chose; the image and its text are never sent anywhere. Nothing about it is loaded at startup, and it needs an internet connection only for that first library download.
- Settings or storage left on a device by a version before v2.0 (including an old app password vault record) are cleaned up automatically on first load; your Google settings, cache, and notes are not affected.

## Current status

Version 2.215.0, build stamp 2026-11-24-SSN-V22150. The catalog write guard. A catalog write can no longer revert a note's fresher state: before writing, the app reads the catalog as it stands in the store and merges per note id, so an entry is never replaced by an older copy of it, an entry a fresher catalog carries is never dropped by a session that simply has not seen it, and an entry another session trashed or deleted is never resurrected by a stale write. An entry this session never changed since it loaded cannot overrule the stored entry at all; when both sides changed an entry, the fresher one wins, and a field the winner never touched, notebook, title, or preview, still takes the other side's newer value, so a rename or a notebook move on one device and an edit on another both survive. When the app writes a note file, the file's front matter and the catalog entry are stamped from the same note state, so the two stores agree after the write. Trash, restore, and Delete Forever work exactly as before.
